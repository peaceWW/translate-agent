# V5 — 上下标与专业符号精准提取与还原方案

> **文档版本**: v5.0  
> **日期**: 2026-09-18  
> **状态**: **备选 / 实验** — 主翻译路径已改为页级视觉大模型（见 [[v6-视觉大模型翻译方案]]）。本方案仅在无法使用 VL 模型、需对平铺文本做离线还原时参考。  
> **依赖**: [[v4-特殊符号翻译问题]] → 本方案在 v4 诊断基础上提出可落地的三阶段流水线  
> **核心思路**: 正则粗筛 → 领域白名单纠偏 → LLM 上下文精修

---

## 1. 问题重述

PDF 提取时，变量与上下标被"平铺"为普通文本：

| PDF 原始渲染 | 提取后的平铺文本 | 期望的标准 LaTeX |
|---|---|---|
| I<sub>pd</sub> | `Ipd` | `$I_{\text{pd}}$` |
| RC<sub>IN</sub> | `RCIN` | `$\text{RC}_{\text{IN}}$` |
| Δv<sub>1</sub> | `Δv1` | `$\Delta v_1$` |
| V<sub>DD</sub> | `VDD` | `$V_{\text{DD}}$` |
| g<sub>m</sub> ∝ √I<sub>d</sub> | `gm ∝ √Id` | `$g_m \propto \sqrt{I_d}$` |
| f<sub>clk</sub> | `fclk` | `$f_{\text{clk}}$` |
| C<sub>ox</sub> | `Cox` | `$C_{\text{ox}}$` |

**根因**：PDF 内部以字形基线偏移表示上下标，PyMuPDF 提取后丢失位置信息，多字符下标被拼接为连续字符串。

---

## 2. 设计原则

1. **不破坏现有管线** — 作为独立后处理模块插入，不修改 `protection.py` / `semantic_builder.py` 核心逻辑
2. **渐进增强** — 正则 → 白名单 → LLM 三层逐级精化，任一层失败不影响后续
3. **领域可配置** — 白名单按论文领域加载，不硬编码
4. **可审计** — 每次替换记录原文、替换结果、匹配规则来源（正则/白名单/LLM），便于 QA 回溯

---

## 4. Stage 1 — 正则粗筛

### 4.1 设计目标

从平铺文本中识别出**疑似变量/上下标片段**，输出候选列表及置信度，不做最终替换。

### 4.2 匹配规则体系

```python
# backend/app/services/subscript_restorer.py

from dataclasses import dataclass
from enum import Enum
import re

class MatchSource(Enum):
    REGEX = "regex"
    GLOSSARY = "glossary"
    LLM = "llm"

@dataclass
class Candidate:
    """一个疑似变量/上下标候选"""
    original: str          # 原始匹配文本, e.g. "Ipd"
    start: int             # 在原文中的起始位置
    end: int               # 在原文中的结束位置
    confidence: float      # 置信度 0.0~1.0
    source: MatchSource    # 匹配来源
    rule_name: str         # 规则名称(用于审计)
    proposed_latex: str    # 建议的LaTeX还原(可能为空,等后续阶段填充)
    context: str           # 上下文窗口(前后各30字符)
```

### 4.3 正则模式定义

```python
PATTERNS = [
    # ─── 模式 A: 单字母 + 数字下标 ───
    # v1, v2, I3, n2 → 高置信度, 数学下标为数字
    (
        "single_letter_numeric_sub",
        r'(?<![a-zA-Z])([a-zA-Z])(\d+)(?![a-zA-Z])',
        0.90
    ),

    # ─── 模式 B: 单字母 + 小写连写下标 ───
    # gm, Id, fn → 中高置信度(可能误伤普通单词,需白名单/LLM消歧)
    (
        "single_letter_lowercase_sub",
        r'(?<![a-zA-Z])([a-zA-Z])([a-z]{1,4})(?![a-zA-Z])',
        0.65
    ),

    # ─── 模式 C: 大写缩写 + 大写下标 ───
    # VDD, VSS, VGS, VDS → 高置信度(电路通用符号)
    (
        "capital_var_capital_sub",
        r'(?<![a-zA-Z])([A-Z])([A-Z]{2,3})(?![a-zA-Z])',
        0.85
    ),

    # ─── 模式 D: 两大写缩写 + 下标 ───
    # RCIN, RCL, CIN → 中置信度(多字母变量名)
    (
        "two_capital_var_sub",
        r'(?<![a-zA-Z])([A-Z]{2})([A-Z]{1,3})(?![a-zA-Z])',
        0.70
    ),

    # ─── 模式 E: 希腊前缀 + 下标 ───
    # Δv1, αmax, ωc → 高置信度(希腊字母几乎总是变量)
    (
        "greek_prefix_sub",
        r'(?<![a-zA-Z])([αβγδεζηθικλμνξπρστυφχψωΔΩΣ∏∫][a-zA-Z0-9]{1,5})(?![a-zA-Z])',
        0.88
    ),

    # ─── 模式 F: 下划线标记法(部分PDF保留) ───
    # V_DD, g_m, C_ox → 极高置信度(下划线即PDF残留)
    (
        "underscore_subscript",
        r'([a-zA-Z]{1,3})_([a-zA-Z0-9]{1,4})',
        0.95
    ),

    # ─── 模式 G: 数字上标 ───
    # x2, n2 (在特定上下文中为平方) → 低置信度(需上下文判断)
    (
        "numeric_superscript",
        r'(?<![a-zA-Z_])([a-zA-Z])(\²|\³|2|3)(?![a-zA-Z0-9])',
        0.50
    ),
]
```

### 4.4 粗筛算法

```python
def coarse_filter(text: str) -> list[Candidate]:
    """
    正则粗筛: 对文本应用所有模式, 收集候选.
    - 多模式重叠时保留置信度最高者
    - 嵌套匹配时保留最长匹配
    - 排除英文常见词(to, in, on, at, an, is, it, of, or, as, be, by, do, go, he, me, no, so, up, us, we)
    """
    STOP_WORDS = {
        "in", "on", "at", "an", "is", "it", "of", "or", "as", "be",
        "by", "do", "go", "he", "me", "no", "so", "up", "us", "we",
        "if", "to", "am", "ok", "not", "and", "but", "for", "the",
        "can", "has", "had", "was", "are", "been", "from", "that",
        "this", "with", "will", "would", "could", "should",
    }

    candidates = []
    for rule_name, pattern, confidence in PATTERNS:
        for m in re.finditer(pattern, text):
            matched = m.group(0)
            if matched.lower() in STOP_WORDS:
                continue
            candidates.append(Candidate(
                original=matched,
                start=m.start(),
                end=m.end(),
                confidence=confidence,
                source=MatchSource.REGEX,
                rule_name=rule_name,
                proposed_latex="",
                context=text[max(0, m.start()-30):m.end()+30],
            ))

    # 去重: 重叠区间保留置信度最高者
    return deduplicate_overlapping(candidates)
```

### 5.1 设计目标

1. 对 Stage 1 候选进行**消歧** — 区分 `Id` 是 "电流变量 $I_d$" 还是英文单词 "Id"

### 5.3 白名单加载与匹配

```python
@dataclass
class GlossaryEntry:
    flat: str           # 平铺形式
    latex: str | None   # LaTeX还原 (null=排除项)
    desc: str           # 描述
    type: str           # subscript / superscript / exclude

class Glossary:
    def __init__(self, domain: str):
        self.entries: dict[str, GlossaryEntry] = {}
        self._load(domain)

    def _load(self, domain: str):
        """从 YAML 加载领域白名单"""
        path = Path(__file__).parent / "glossaries" / f"{domain}.yaml"
        if path.exists():
            data = yaml.safe_load(path.read_text(encoding="utf-8"))
            for e in data["entries"]:
                self.entries[e["flat"]] = GlossaryEntry(**e)

    def lookup(self, flat: str) -> GlossaryEntry | None:
        """精确匹配(区分大小写)"""
        return self.entries.get(flat)

    def fuzzy_lookup(self, flat: str) -> GlossaryEntry | None:
        """模糊匹配: 容忍大小写差异, 但不匹配 exclude 项"""
        entry = self.entries.get(flat)
        if entry and entry.type == "exclude":
            return None
        if entry:
            return entry
        # 尝试大小写不敏感匹配
        for key, entry in self.entries.items():
            if key.lower() == flat.lower() and entry.type != "exclude":
                return entry
        return None
```

### 5.4 Stage 2 纠偏逻辑

```python
def glossary_refine(
    candidates: list[Candidate],
    glossary: Glossary,
) -> tuple[list[Candidate], list[Candidate]]:
    """
    白名单纠偏: 将候选分为 "已确认" 和 "待LLM处理" 两组.
    - 命中且 latex 非空 → 直接填充 proposed_latex, 置信度提升至 0.99
    - 命中且 type=exclude → 移除该候选(是普通单词)
    - 未命中 → 保留, 标记为待 LLM 处理
    """
    confirmed, pending_llm = [], []

    for c in candidates:
        entry = glossary.fuzzy_lookup(c.original)
        if entry is None:
            # 未命中白名单, 交给 LLM
            c.source = MatchSource.GLOSSARY  # 标记已检查白名单
            pending_llm.append(c)
        elif entry.type == "exclude":
            # 排除项, 丢弃
            continue
        elif entry.latex:
            # 命中, 直接给出 LaTeX
            c.proposed_latex = f"${entry.latex}$"
            c.confidence = 0.99
            c.source = MatchSource.GLOSSARY
            c.rule_name = f"glossary:{entry.desc}"
            confirmed.append(c)

    return confirmed, pending_llm
```

## 6. Stage 3 — LLM 上下文精修

### 6.1 设计目标

对 Stage 2 未命中的候选，利用 LLM 的语义理解能力，结合**原文上下文**和**领域术语表**，做最终的消歧与 LaTeX 还原。

### 6.2 Prompt 设计

```python
LLM_PROMPT_TEMPLATE = """你是一位光电集成电路领域的 LaTeX 排版专家。

## 任务
请检查以下文本中的"疑似变量/上下标"片段，结合领域术语词表，判断每个片段是：
A) 物理变量/参数 → 给出标准 LaTeX 格式还原
B) 普通英文单词 → 标记为 skip

## 领域术语词表
{glossary_summary}

## 待检查片段
{candidates_block!s}

## 规则
1. 变量的下标用 _{{\\text{{下标}}}} 格式（9,0,1 等纯数字下标用 _数字)
2. 变量的上标用 ^{{上标}} 格式
3. 希腊字母用 \\alpha, \\beta, \\Delta 等 LaTeX 命令
4. 不要修改普通英文单词（如 "the", "and", "input" 等）
5. 每个片段必须-行输出: 片段 | 判断(A/B) | LaTeX还原(仅A类)

## 输出格式(严格JSON)
```json
[
  {{"original": "Ipd", "verdict": "A", "latex": "I_{{\\text{{pd}}}}"}},
  {{"original": "1n", "verdict": "B", "latex": null}}
]
```"""
```

### 6.3 LLM 调用与结果解析

```python
async def llm_refine(
    text: str,
    pending: list[Candidate],
    glossary: Glossary,
    llm_client,  # 复用现有 services/llm.py 的 LLM 客户端
) -> list[Candidate]:
    """
    LLM 上下文精修:
    1. 将未命中候选及其上下文构造 Prompt
    2. 调用 LLM (复用项目已有的 OpenAI 兼容接口)
    3. 解析 JSON 响应, 更新候选的 proposed_latex
    4. 解析失败 → 保留候选但不填充 latex (后续 QA 可检出)
    """
    if not pending:
CANDIDATES:
        return []

    # 构造 Prompt
    glossary_summary = "\n".join(
        f"- {e.flat} → ${e.latex}$ ({e.desc})"
        for e in glossary.entries.values()
        if e.latex  # 只展示有效条目
    )

    candidates_block = "\n".join(
        f"- 片段: \"{<arg>}"
        for <arg> in pending
    )   # each candidate shows: original, context

    prompt = LLM_PROMPT_TEMPLATE.format(
        glossary_summary=glossary_summary,
        candidates_block=candidates_block,
    )

    # 调用 LLM (复用项目已有的 services/llm.py)
    response = await llm_client.chat(
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1,  # 低温度保证稳定输出
        response_format={"type": "json_object"},
    )

    # 解析 JSON 响应
    try:
        results = json.loads(response)
        result_map = {r["original"]: r for r in results}
        for c in pending:
            r = result_map.get(c.original)
            if r and r["verdict"] == "A" and r.get("latex"):
                c.proposed_latex = f"${r['latex']}$"
                c.confidence = 0.92
                c.source = MatchSource.LLM
                c.rule_name = "llm_refine"
    except (json.JSONDecodeError, KeyError):
        # 解析失败, 保留候选但不填充 — QA 可检出这些未还原项
        pass

    return pending
```

## 7. 流水线编排与集成点

### 7.1 主入口

```python
class SubscriptRestorer:
    """上下标还原流水线 — 正则粗筛 → 白名单纠偏 → LLM精修"""

    def __init__(self, domain: str = "photonic_ic", llm_client=None):
        self.glossary = Glossary(domain)
        self.llm_client = llm_client

    async def restore(self, text: str) -> RestoredResult:
        """
        执行三阶段还原.
        返回: 还原后文本 + 替换日志
        """
        # Stage 1: 正则粗筛
        candidates = coarse_filter(text)
        if not candidates:
            return RestoredResult(text=text, log=[])

        # Stage 2: 白名单纠偏
        confirmed, pending = glossary_refine(candidates, self.glossary)

        # Stage 3: LLM 精修 (仅对未命中白名单的候选)
        if pending and self.llm_client:
            await llm_refine(text, pending, self.glossary, self.llm_client)

        # 合并所有已确认的候选
        all_confirmed = confirmed + [c for c in pending if c.proposed_latex]

        # 执行文本替换 (从后向前, 避免偏移错乱)
        result_text, log = apply_replacements(text, all_confirmed)

        return RestoredResult(text=result_text, log=log)


@dataclass
class ReplaceLog:
    original: str
    replacement: str
    position: int
    source: MatchSource
    rule_name: str
    confidence: float

@dataclass
class RestoredResult:
    text: str
    log: list[ReplaceLog]
```

### 7.2 集成到现有管线

```
现有管线:
  PDF Parse → SemanticBuilder → StructuredTranslator → QA → PDF Compose

插入点 (两处):

  ┌─────────────┐    ┌──────────────────┐    ┌──────────────────┐
  │  PDF Parse  │───→│ SubscriptRestorer│───→│  SemanticBuilder │ → ...
  └─────────────┘    │  (预处理: 还原原文) │    └──────────────────┘
                     └──────────────────┘

  ┌──────────────────┐    ┌──────────────────┐    ┌────────────┐
  │StructuredTranslator│───→│ SubscriptRestorer│───→│    QA      │ → ...
  │  (翻译后)         │    │  (后处理: 修正译文) │    └────────────┘
  └──────────────────┘    └──────────────────┘

**预处理（翻译前）**：对 PDF 提取的原文执行还原，使 LLM 翻译时看到的是标准 LaTeX 格式，避免误翻变量名。

**后处理（翻译后）**：对 LLM 输出译文执行还原，捕获 LLM 可能将变量平铺的情况（如 LLM 将 $I_{\text{pd}}$ 误写为 `Ipd`）。

## 9. 替换执行与防冲突

### 9.1 从后向前替换

```python
def apply_replacements(
    text: str,
    candidates: list[Candidate],
) -> tuple[str, list[ReplaceLog]]:
    """
    执行文本替换:
    1. 按位置从后向前排序(避免偏移错乱)
    2. 跳过重叠区间
    3. 记录每次替换的日志
    """
    # 过滤: 只替换有 proposed_latex 的候选
    valid = [c for c in candidates if c.proposed_latex and c.confidence >= 0.7]
    # 排序: 从后向前
    valid.sort(key=lambda c: c.start, reverse=True)

    result = text
    log = []
    last_end = len(text)  # 防重叠: 追踪已替换区间

    for c in valid:
        if c.end > last_end:
            continue  # 与后续替换重叠, 跳过

        result = result[:c.start] + c.proposed_latex + result[c.end:]
        log.append(ReplaceLog(
            original=c.original,
            replacement=c.proposed_latex,
            position=c.start,
            source=c.source,
            rule_name=c.rule_name,
            confidence=c.confidence,
        ))
        last_end = c.start

    return result, log
```

### 9.2 与现有保护系统的协同

```python
# 关键: SubscriptRestorer 的替换结果会被 protection.py 的
# mask_scientific_content() 进一步处理.
#
# 还原后的 LaTeX (如 $I_{\\text{pd}}$) 会被 LaTeX 模式
# (mask_scientific_content 中的 $$...$$ 和 $...$ 规则)
# 自动识别为 KEEP 区域, 确保 LLM 翻译时不触碰.
#
# 因此: SubscriptRestorer → protection.mask → LLM → protection.restore
# 形成完整的保护链.
```

## 11. QA 集成

### 11.1 替换日志审计

```python
# 在 QA 阶段, 检查替换日志中是否有:
# 1. 置信度 < 0.7 的替换 → 低置信度, 可能误判
# 2. source=LLM 且 proposed_latex 含异常字符 → LLM 幻觉风险
# 3. 同一原文在文中出现多次但还原不一致 → 不一致问题

def audit_replace_log(log: list[ReplaceLog]) -> list[QAWarning]:
    warnings = []
    for entry in log:
        if entry.confidence < 0.7:
            warnings.append(QAWarning(
                level="low_confidence",
                msg=f"低置信度替换: '{entry.original}' → '{entry.replacement}' "
                    f"(置信度={entry.confidence:.2f}, 来源={entry.source.value})",
            ))
        if entry.source == MatchSource.LLM and "\\" not in entry.replacement:
            warnings.append(QAWarning(
                level="suspicious_llm",
                msg=f"LLM还原缺少LaTeX命令: '{entry.original}' → '{entry.replacement}'",
            ))
    return warnings
```

### 11.2 数值保真检查（复用现有 QA）

还原后的 LaTeX 变量（如 `$V_{\text{DD}}$`）会被 `protection.py` 的 `$...$` 模式自动捕获为 KEEP 区域，因此现有的数值/符号保真检查机制自动生效，无需额外开发。

## 14. 可行性评估

### ✅ 技术可行性

- **Stage 1 正则**: 完全可行。项目已有 `SUBSCRIPT_VAR_PATTERN` 等成熟正则，本方案是对其的**扩展与系统化**，非从零开始。
- **Stage 2 白名单**: 完全可行。YAML 配置 + 精确匹配是确定性逻辑，零风险。`terminology.py` 在项目规划中本就存在（当前仅有 `.pyc`），白名单是其具体落地形式。
- **Stage 3 LLM**: 完全可行。项目已有 `services/llm.py` 的 OpenAI 兼容客户端，直接复用。Prompt 工程是成熟技术，低温度 + JSON 格式约束可保证输出稳定性。

### ✅ 架构兼容性

- 作为**独立模块** `subscript_restorer.py` 插入，不修改 `protection.py` / `semantic_builder.py` 核心代码。
- 还原后的 LaTeX 会被现有 `mask_scientific_content()` 自动保护，**天然协同**。
- 预处理/后处理集成点明确，通过配置开关控制。

### ✅ 渐进交付

- Phase 1+2 即可独立运行（正则 + 白名单），不依赖 LLM。
- Phase 3 可按需开启，不强制。
- 每个阶段独立测试，不阻塞其他阶段。

### ⚠️ 需注意

- 白名单需要**持续积累**，初始覆盖率有限（Phase 2 预计 30-50 个条目）。
- 正则模式对 `f3dB` 等混合大小写+数字的结构覆盖不足，需补充模式或依赖 LLM 兜底。
- LLM 精修对**长文档**可能需要分批调用（每次 10-20 个候选），控制 prompt 长度。
