# V1 待修复问题清单

> 以下问题基于 IEEE/ACM 芯片设计类学术论文的典型场景梳理，涉及版面保真与内容保真两个维度。

---

## 问题一：角标 / 上下标在翻译过程中丢失或错位

### 现象

PyMuPDF 提取文本时，部分上标、下标信息被平铺为普通字符，导致翻译后再合成 PDF 时原始语义关系断裂。典型表现：

| 原文语义 | 提取后 | 合成后 |
|---|---|---|
| α₋₁（下标 −1） | `α-1` 或 `α1` | α−1 或 α1（下标丢失） |
| V<sub>DD</sub>（电源电压） | `VDD` | VDD（下标被吞） |
| f<sub>clk</sub> = 10 GHz | `fclk = 10 GHz` | fclk = 10 GHz（下标丢失） |
| 2<sup>N</sup> − 1（二进制系数） | `2N - 1` | 2N − 1（上标丢失） |

### 芯片设计论文中的影响

在模拟 / 混合信号芯片论文中，上下标不是"排版装饰"，而是**语义核心**：

- **器件参数**：g<sub>m</sub>（跨导）、C<sub>ox</sub>（氧化层电容）、V<sub>th</sub>（阈值电压）—— 丢失下标会导致参数含义完全改变
- **工艺节点**：65 nm CMOS、28 nm FinFET —— 节点数字不可被翻译或修改
- **信号标注**：V<sub>in+</sub> / V<sub>in−</sub>（差分输入）—— 下标中的 +/− 代表极性，丢失即改变电路语义
- **频域表达**：H(jω)、S<sub>21</sub>(f) —— 上标/下标同时出现，必须完整保留

### 根因

PyMuPDF 的 `page.get_text("dict")` 接口按视觉块返回文本，**不区分基线字符与上/下标字符**。当字符 y 坐标偏移量小于阈值时，上下标信息被丢弃。

### 建议修复方向

1. 在 `PDFParserService` 中增加**上下标检测**：比较字符 y 坐标与行基线的偏移量和字号差异，将偏移超过阈值的字符标记为 `superscript` 或 `subscript`
2. 在 `LayoutBlock` schema 中新增 `subscript: bool` / `superscript: bool` 字段
3. 在 `PDFComposerService` 合成时，对标记为上/下标的字符使用 PyMuPDF 的 `insert_text` 配合字号缩放和基线偏移还原
4. 对识别为上下标的段落，自动归入 **保护区**（`translate: false`），禁止 LLM 改写

## 问题二：图表引用编号在合成 PDF 中被重编号

### 现象

原始 PDF 中的图片引用如 `Fig. 4`、`Table II` 在合成后的译文中被 PyMuPDF 重新编号，导致：

```
原文：  如图 Fig. 4 所示……
译文：  如图 Fig. 3 所示……     ← 编号错位，与实际图不对应
```

对应的，文档中的交叉引用图片也被重新命名：

| 原始引用 | 合成后 | 后果 |
|---|---|---|
| `Fig. 4` | `Fig. 3` | 正文中引用与实际图编号不匹配 |
| `Table II` | `Table 2` | 罗马数字 → 阿拉伯数字，不符合 IEEE 规范 |

### 芯片设计论文中的影响

芯片论文中图表编号是**硬性引用锚点**，在全文中可能被引用数十次：

- **架构图引用**："The proposed hybrid ADC architecture is shown in **Fig. 4**" —— 若 Fig. 4 变成 Fig. 3，读者无法定位
- **性能对比表引用**："The performance summary is listed in **Table II**" —— 编号改变后与后文 Comparison Table 不对应
- **多图子标引用**：Fig. 4(a)、Fig. 4(b) 代表同一架构的不同模块，编号错位会混淆子图关系
- **跨页引用**：芯片论文常跨 8-12 页，Fig. 4 可能在第 3 页定义而在第 8 页被引用，编号一致性必须全文保证

### 建议修复方向

1. **禁用 PyMuPDF 自动重编号**：在 `pdf_composer.py` 中合成 PDF 时，确保图/表编号使用原文中提取的原始编号，而非让 PyMuPDF 重新分配
2. **将 Fig./Table 编号加入保护区**：在 `protection.py` 中扩展保护规则，识别 `Fig.\s*\d+`、`Table\s+[IVX\d]+` 模式并锁定
3. **全文交叉引用一致性校验**：在 QA 层增加"定义-引用"一致性检查，确保每个 Fig./Table 编号在全文中出现时的值一致

## 问题三：术语库策略需调整 — 专业论文中术语以首次定义 + 后续英文简称为主

### 现象

当前系统维护了一个术语库（Terminology Book），试图在全文中统一将英文术语翻译为中文全称。但这一策略与芯片设计专业论文的实际写作惯例不符。

### 芯片设计论文的术语惯例

在 IEEE TCAS、JSSC、ISSCC 等顶级期刊的中文翻译中，术语处理遵循以下规范：

| 阶段 | 处理方式 | 示例 |
|---|---|---|
| **首次出现** | 英文全称 + 中文释义 + 缩写 | "Analog-to-Digital Converter (ADC, 模数转换器)" |
| **后续出现** | 仅使用英文缩写 | "The ADC achieves …" |
| **已成通用缩写** | 全文不翻译 | ADC、DAC、PLL、VCO、LNA、OP-AMP |
| **物理量/单位** | 绝不翻译 | dB、GHz、nm、mW、mm² |

也就是说：

> **专业论文中，术语只在首次出现时给出中文解释，其余地方一律保留英文简称。**

强行全文统一翻译为中文全称（如每次都将 ADC 翻译为"模数转换器"），会导致：

1. **与中文芯片论文的写作规范相悖** —— 中文芯片论文同样使用 ADC/PLL/VCO 等缩写
2. **降低可读性** —— 读者熟悉的是缩写，不是冗长的中文全称
3. **破坏版面** —— 中文全称字符宽度远大于英文缩写，挤压原文版式空间

### 建议调整方向

1. **术语库改为"首现释义表"**：仅记录术语的首次出现位置和中文释义，不在后续出现时替换
2. **保护区规则扩展**：将已成通用缩写的术语（ADC、DAC、PLL、VCO、LNA、OP-AMP、DFE、FFE、ISI、SAR、CTLE …）加入保护区，**禁止翻译**
3. **翻译 Prompt 优化**：在发给 LLM 的翻译指令中明确说明——"对已定义的术语缩写保留英文原文，仅在首次出现时补充中文注释"
4. **保留术语库功能但调整默认策略**：术语库可用于"一致性检查"（确保同一缩写全文统一），而非"全文替换"

## 优先级排序

| 优先级 | 问题 | 影响范围 | 修复复杂度 |
|---|---|---|---|
| 🔴 P0 | 图表引用编号错位 | 全文引用体系崩溃，读者无法定位图表 | 中 |
| 🔴 P0 | 上下标丢失 | 器件参数语义改变，公式含义错误 | 中-高 |
| 🟡 P1 | 术语库策略调整 | 输出不符合专业论文规范，版面被挤压 | 低 |

> **P0 问题不解决，翻译结果在芯片设计领域不可用** —— 参数含义改变和图表编号错位属于"硬伤"，无论译文语句多流畅都无法弥补。
