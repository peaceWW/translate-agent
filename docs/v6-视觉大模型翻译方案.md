# V6 — 视觉大模型翻译主路径

> **文档版本**: v6.0  
> **日期**: 2026-09-18  
> **取代关系**: 翻译质量主路径由「文本 + 规则猜上下标」改为「页级视觉翻译」；[[v5-上下标与专业符号提取方案]] 降为实验/备选。  
> **不变**: PDF 解析、保护区、Composer 回写、前端工作台、逐页发布。

---

## 1. 需求与结论

| 维度 | 结论 |
|------|------|
| 痛点 | PDF 上下标/根号以字形偏移绘制，平铺文本失真；正则/白名单/`[[KEEP]]` 猜还原效果差 |
| 目标 | 只用视觉大模型读懂版式后再翻译 |
| 不变 | Layout 解析、排版合成、QA 入口、上传与进度 |
| 策略 | **页级**：整页 PNG + `source_id/bbox/text_hint` 一次翻译；失败块回退文本翻译 |

---

## 2. 之前架构（文本驱动）

```text
PDF → Parser(LayoutBlock) → StructuredTranslator / TranslationAgent
    → protection KEEP / 符号硬校验 → PageRepair → Composer → PDF
```

翻译输入是**已失真的字符串**，后续规则在弥补解析损失。

---

## 3. 调整后架构（视觉驱动翻译）

```text
PDF ─┬→ Parser(LayoutBlock, 几何不变)
     └→ PageRenderer(page PNG)
              ↓
     VisionTranslationAgent(页图 + 区块 JSON)
              ↓ 失败块
     TranslationAgent 文本回退 → PageRepair(可选)
              ↓
     QA(符号软告警) → Composer(契约不变) → PDF
```

| 环节 | 之前 | 现在 |
|------|------|------|
| 翻译输入 | `block.text` | **页图 + 区块清单** |
| 符号保真 | 正则 / KEEP / 硬校验 | 模型看字形；符号计数软告警 |
| 模型调用 | 每页多路 block | **每页 1 次**视觉调用 |
| Composer | `TranslatedBlock` | **不变** |
| v5 上下标流水线 | 拟为主路径 | **备选**，默认不启用 |

---

## 4. 关键模块

| 模块 | 路径 |
|------|------|
| 页渲染 | `backend/app/services/page_renderer.py` |
| 视觉翻译 Agent | `backend/app/agents/vision_translator.py` |
| 多模态 LLM | `LLMService.chat_with_images` |
| 配置 | `LLMConfig.vision_model / vision_base_url / vision_api_key / vision_scale` |
| 编排 | `DocumentAgent._translate_pages` 主路径改视觉 |

---

## 5. 配置说明

在「模型配置」中设置视觉模型，例如：

- 通义：`qwen-vl-max` + DashScope compatible endpoint  
- OpenAI：`gpt-4o`  
- 留空且主模型名不含 VL 特征时 → 自动走原文本翻译管线  

页图缓存：`data/docs/{doc_id}/runs/{run_id}/page-images/page-{n}.png`

---

## 6. 回归建议

1. 配置 VL 模型后翻译含 `g_m ∝ √I_d`、`I_pd` 的 IEEE 样本页  
2. 确认 `layout_report.translation_mode == "vision"`，失败块有 `text_fallbacks`  
3. Composer 仍按 bbox 回写，图/公式像素保护区无回归  
4. 单元测试：`python -m unittest tests.test_vision_translation`
