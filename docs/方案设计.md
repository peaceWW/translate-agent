对，这会直接改变项目的设计重点。这个项目不能只定义为“专业 PDF 翻译”，而应该定义为：

> **在尽可能保持原 PDF 视觉版式和学术结构的前提下，对正文进行专业、可校验的翻译，并确保术语、公式、图表、引用、数值不被错误改写。**

你上传的 IEEE 论文就是很典型的压力测试样本：双栏排版、页眉页脚、Fig. 图注、复杂架构图、公式、参考文献、章节编号都存在。例如第 6 页的公式中 `α−1`、`α1` 与二进制系数存在严格对应关系，这类内容必须进入“保护区”，而不能让翻译模型自由生成。

因此我会把前面的方案改成 **“版面保真 + 内容保真”双引擎架构**。

### 1. 排版一致：不能“翻译后重新生成一份差不多的 PDF”

系统首先解析 PDF 的 Layout Tree：

```text
Page
 ├── Header
 ├── Column Left
 │    ├── Title
 │    ├── Paragraph
 │    ├── Figure
 │    └── Caption
 ├── Column Right
 │    ├── Paragraph
 │    ├── Formula
 │    └── Paragraph
 ├── Footer
 └── Page Number
```

每一个元素保存原始坐标：

```json
{
  "page": 6,
  "type": "formula",
  "bbox": [x1, y1, x2, y2],
  "source_id": "formula_001",
  "translate": false
}
```

翻译过程中**只替换允许翻译的 Text Block**。

图片、公式、坐标关系、编号、参考文献引用尽量保持原样。

最终不是：

```text
PDF → Text → 翻译 → 新 PDF
```

而是：

```text
                 原始 PDF
                    ↓
            Layout Reconstruction
                    ↓
       ┌────────────┼─────────────┐
       ↓            ↓             ↓
   Text Block     Figure        Formula
       ↓            ↓             ↓
     翻译          保留            保留
       │            │             │
       └────────────┼─────────────┘
                    ↓
              Layout Composer
                    ↓
            Translated PDF
```



### 2. 中文长度变化，要有“自适应排版”

这是实际开发最容易踩坑的地方。

英文：

> The proposed hybrid ADC-based receiver architecture...

翻译成中文后字符宽度、换行位置、段落高度都可能变化。

所以不能要求绝对的“像素级文字位置完全一致”，合理目标应该定义为：

**视觉结构一致，而不是每个字符坐标一致。**

也就是：

```text
原文                         译文

Page 3                       Page 3
双栏                          双栏

Fig.2                        Fig.2
[原图]                        [原图]

Caption                      中文 Caption

正文                          中文正文

Fig.3                        Fig.3
[原图]                        [原图]

公式                          原公式
```

排版引擎采用：

```text
优先级：

① 保持页面结构
② 保持图/表/公式位置关系
③ 保持章节顺序
④ 保持引用关系
⑤ 调整中文字距/字号
⑥ 必要时局部重新分页
```

**绝对不要为了硬塞进原来的 Text Box，把中文字体缩到非常小。**

### 3. 内容准确：不能只有一个 Translation Agent

建议改成：

```text
              Translation Agent
                     │
                     ▼
              Candidate Translation
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
     Terminology   Fidelity   Structure
       Checker      Checker     Checker
          │          │          │
          └──────────┼──────────┘
                     ▼
                QA Reviewer
                     │
              ┌──────┴──────┐
              │             │
             PASS          FAIL
              │             │
              ▼             ▼
            入库          重新翻译
```

而且要把内容分成两类：

**Protected Content**

```text
公式
变量
数字
单位
引用编号
DOI
作者
参考文献
图编号
表编号
器件型号
工艺节点
```

原则上禁止模型修改。

**Translatable Content**

```text
Title
Abstract
Section Title
Paragraph
Figure Caption
Table Text
Footnote
```

例如附件原文说的是 10 Gb/s、GP 65 nm CMOS、0.81 mm²、最高 36.4 dB attenuation，以及接收机功耗低于 90 mW。

这些数据经过翻译以后必须还是：

```text
10 Gb/s       → 10 Gb/s
65 nm         → 65 nm
0.81 mm²      → 0.81 mm²
36.4 dB       → 36.4 dB
90 mW         → 90 mW
```

QA Agent 应该程序化比对这些内容，而不是仅仅问另一个 LLM“翻译得准不准”。

---



### 4. 内容准确性建议做“三层校验”

第一层是**程序校验**，检查数字、单位、公式、引用、Fig/Table 编号、缩写是否丢失。

第二层是**术语校验**，维护：

```text
Source                     Target

ADC                         模数转换器
FFE                         前馈均衡器
DFE                         判决反馈均衡器
ISI                         码间干扰
SAR                         逐次逼近寄存器
```

同一个术语全文原则上只能有一个规范译法。

第三层才是 **LLM Semantic Reviewer**，输入：

```text
原文
+
译文
+
上一段
+
下一段
+
章节摘要
+
术语表
```

让模型判断是否存在：

```text
漏译
错译
反义
主语错误
逻辑关系改变
技术概念改变
因果关系改变
程度词改变
```

这样比简单的“一次 LLM 翻译”可靠得多。

然后点击任意中文段落，右侧弹出：

这会比我上一版原型中的“普通左右翻译结果”专业很多。

### 6. 产品验收标准也要提前写死

最终不要用“感觉翻译挺准”作为验收标准，而应该定义几个硬指标：


| 指标              | 目标           |
| --------------- | ------------ |
| 数字保真            | 100%         |
| 单位保真            | 100%         |
| 公式保真            | 100%         |
| Figure/Table 编号 | 100%         |
| Reference 引用关系  | 100%         |
| 术语一致率           | ≥99%         |
| 段落漏译率           | 0%           |
| 页面阅读顺序          | 100%         |
| 图文关联关系          | 100%         |
| 学术语义准确性         | AI 审校 + 人工抽检 |
| PDF 版式          | 高度接近原稿       |


**这里我建议不要承诺“100% 原版 PDF 排版完全一致”。** 因为英文和中文天然存在字体、字符宽度和段落长度差异。

更专业的产品定义应该是：

> **Layout Fidelity：保持页面、双栏、章节、图片、公式、表格、图注及上下文关系高度一致；文字区域允许自适应重排。**

这样项目的技术目标才是可实现、可验收的。

最终这个 Agent 的核心竞争力就可以浓缩成四句话：

> **看得懂 PDF 结构。**
> **翻得懂专业知识。**
> **不破坏公式、图表和数据。**
> **翻译后仍然像原来的论文。**

这也意味着我们前面那张产品原型需要升级，我建议下一版直接围绕 **“原 PDF / 译文 PDF 双栏对照 + 段落级审校 + QA 检测 + 术语锁定 + 模型配置”** 来设计，而不是普通 AI 翻译网站。
