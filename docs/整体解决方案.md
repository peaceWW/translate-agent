有，而且我认为你现在碰到的已经不是“再优化几个碰撞判断”能彻底解决的问题，而是**当前 PDF 翻译的建模方式需要换掉**。

你列出的 5 个问题，本质上其实是三类冲突：

| 问题                   | 本质                                    |
| -------------------- | ------------------------------------- |
| `kT/CIN = IpdTb` 被保护 | 公式与正文被解析成同一个/重叠 Block                 |
| `CINkT (6)`          | 公式、公式编号、正文阅读顺序识别错误                    |
| `gm ∝ √...`          | 一句话横跨正文和公式，保护区把句子截断                   |
| `Δv... = ...`        | 行内/展示公式被误认为独立图形                       |
| Fig.10(a)... 丢失      | LLM 被要求“翻译文本同时保证保护 Token 完整”，失败后整个块回退 |

所以目前这种：

```text
PDF
→ bbox 文本块
→ 判断是否撞公式/图片
→ 撞了就保护
→ 翻译
→ 覆盖回原坐标
```

继续修下去会越来越复杂。

我建议换成一个核心思路：

> **不要再让“PDF物理坐标”决定什么可以翻译，而是先重建论文的语义文档，再让“语义文档”和“PDF坐标”分别负责内容与排版。**

---

# 一、最关键的改变：从 Block 翻译升级成 Document AST

现在可能类似：

```text
Block 101
bbox=[...]
text="The input noise kT/CIN = IpdTb ..."
```

然后发现 bbox 和公式相交。

以后应该解析成：

```text
Paragraph
 ├── Text("The input noise ")
 ├── InlineFormula("kT/CIN = IpdTb")
 ├── Text(" results in ...")
```

也就是说：

### PDF 的视觉块 ≠ 翻译块。

真正给 LLM 的应该是：

```xml
<p>
The input noise
<formula id="F23"/>
results in ...
</p>
```

模型只翻译：

```text
The input noise
results in ...
```

最后：

```text
输入噪声
<formula id="F23"/>
导致……
```

再把原始：

$$
kT/C_{IN}=I_{pd}T_b
$$

插回去。

这样根本不存在：

> 与公式保护区相交，所以整块保留原文。

这个概念应该从系统里逐渐取消。

---

# 二、把论文拆成「语义层」和「视觉层」

这是我最推荐你调整的架构。

```text
                   PDF
                    │
             ┌──────┴──────┐
             ↓             ↓
       Visual Parser   Semantic Parser
             │             │
             ↓             ↓
        Layout Tree     Document AST
             │             │
       坐标/字体/栏位     章节/段落/公式
       图片/大小         图注/引用/术语
             │             │
             └──────┬──────┘
                    ↓
              Element Mapping
```

最终同一个元素拥有两种身份：

```json
{
  "id": "element_128",
  "semantic": {
    "type": "inline_formula",
    "content": "kT/C_IN = I_pd T_b"
  },
  "visual": {
    "page": 3,
    "bbox": [221, 341, 388, 362],
    "font": "...",
    "fontSize": 9
  }
}
```

**Semantic 决定“怎么翻译”。**

**Visual 决定“翻译完放哪里”。**

这两个东西不能继续混在一起。

---

# 三、尤其不要再把公式简单定义成“保护矩形”

这是你现在第 3、5、6 页问题的直接来源。

公式实际上至少应该分三种。

### A. 行内公式

例如：

```text
The noise is proportional to gm ∝ √Id.
```

应该解析：

```text
Text
InlineFormula
Text
```

然后翻译：

```text
噪声与 <formula_31> 成比例。
```

### B. 独立公式

例如：

```text
          kT
CIN = ----------
          ...
                    (6)
```

应该是：

```text
Equation {
   body: ...
   number: "(6)"
}
```

整个不翻译。

### C. 混合公式

这是最麻烦的一种：

```text
where gm is the transconductance...
```

或者：

```text
gm ∝ √Id
```

旁边还有英文说明。

不能整块截图保护。

必须继续拆：

```text
FormulaToken
TextToken
FormulaToken
```

所以公式检测建议从：

> **区域检测**

升级成：

> **Token/Span 级数学表达识别。**

---

# 四、第 5 页这个问题就是典型例子

你现在得到：

> 给定增益下，若带宽从 0.7× 数据速率减半至 0.35× 数据速率，则 Rd 可加倍，gm 可减半。由于 gm ∝ √

然后后面被切断。

这说明当前算法大概做了：

```text
中文文本区域
─────────────┐
由于 gm ∝ √ │ ← 撞到 Formula bbox
─────────────┘
              █████████
              Formula
```

于是算法认为：

```text
collision == true
→ rollback
```

但语义上应该先恢复完整句：

```text
[Text]
给定增益下……
由于

[Formula]
gm ∝ √(...)

[Text]
，因此……
```

再排版。

所以建议增加一个：

## Sentence Reconstruction Agent

顺序变成：

```text
PDF Blocks
    ↓
Reading Order
    ↓
Line Merge
    ↓
Sentence Reconstruction
    ↓
Math Span Detection
    ↓
Semantic Paragraph
```

**不要拿 PDF 原始 Block 直接翻译。**

# 五、Fig.10(a) 这种问题，更不应该让 LLM负责保护

你现在的错误：

> 译文丢失关键保护内容：Fig. 10(a), Fig. 10(c), Fig. 10(d), Fig. 9(b), Fig. 3

这个设计我建议直接改掉。

目前应该类似：

```text
Translate the following text.

IMPORTANT:
You MUST preserve:
Fig. 10(a)
Fig. 10(c)
Fig. 10(d)
Fig. 9(b)
Fig. 3
```

然后模型偶尔：

```text
Fig. 10(a)
→ 图10(a)
```

你的程序一比：

```text
"Fig. 10(a)" != "图10(a)"
```

就认为：

```text
保护内容丢失
→ 整块失败
```

这其实是架构问题。

# 六、改成 Placeholder Translation

翻译前程序自己替换：

```text
As shown in Fig. 10(a), Fig. 10(c) and Fig. 10(d)...

↓

As shown in
[[REF_FIG_10_A]],
[[REF_FIG_10_C]]
and
[[REF_FIG_10_D]]...
```

LLM 得到：

```text
As shown in [[REF_FIG_10_A]] ...
```

返回：

```text
如 [[REF_FIG_10_A]] 所示……
```

程序再恢复：

```text
如图 10(a) 所示……
```

数据库：

```json
{
  "REF_FIG_10_A": {
    "type": "figure_reference",
    "target": "figure_10_a",
    "source": "Fig. 10(a)",
    "targetText": "图 10(a)"
  }
}
```

公式也是一样：

```text
gm ∝ √(...)
       ↓
[[MATH_00381]]
```

引用：

```text
[12]
↓
[[CITATION_12]]
```

单位：

```text
0.7×
↓
[[VALUE_191]]
```

甚至 DOI：

```text
[[DOI_01]]
```

这样 LLM 根本没有机会破坏它。

---

# 七、但 Placeholder 也不要无限堆

这里还有一个很容易出现的第二代问题。

假设给 LLM：

```text
[[MATH_1]] [[MATH_2]] [[FIG_3]]
[[CITATION_2]] [[UNIT_7]]
```

几十个 Placeholder 后，模型还是可能：

* 调换顺序；
* 重复；
* 删除；
* 修改括号。

所以更好的方法是：

## Structured Translation

不要让模型返回字符串。

要求返回：

```json
{
  "segments": [
    {
      "type": "text",
      "source_id": "T01",
      "translation": "在给定增益条件下，"
    },
    {
      "type": "ref",
      "id": "MATH_01"
    },
    {
      "type": "text",
      "source_id": "T02",
      "translation": "因此可以得到……"
    }
  ]
}
```

原始结构：

```json
[
  {"type":"text","id":"T01"},
  {"type":"math","id":"MATH_01"},
  {"type":"text","id":"T02"}
]
```

程序检查：

```text
T01 ✓
MATH_01 ✓
T02 ✓

顺序 ✓
数量 ✓
类型 ✓
```

**让 LLM 翻译 Text Node，而不是让 LLM 重写整个 Paragraph。**

可靠性会明显提高。

---

# 八、排版也不要坚持“原坐标硬覆盖”

这是另外一个根本问题。

如果你要求：

> 中文必须塞进英文原来的 bbox。

那么永远会存在：

```text
文字变长
↓
bbox 放不下
↓
字体缩小
↓
碰公式
↓
继续缩小
↓
缺字
↓
rollback 原文
```

这是死循环。

应该采用 **Constraint Layout**。

把页面理解成：

```text
┌──────────────────────────┐
│ Header             LOCK  │
├────────────┬─────────────┤
│ Paragraph  │ Paragraph   │
│   FLOW     │   FLOW      │
│            │             │
│ ┌────────┐ │             │
│ │ Figure │ │ Equation    │
│ │ LOCK   │ │ LOCK        │
│ └────────┘ │             │
│ Caption    │ Paragraph   │
│ FLOW       │ FLOW        │
└────────────┴─────────────┘
```

只有两类：

**LOCK**

```text
Figure
Formula
Table
Page header
特殊符号
```

位置尽量不动。

**FLOW**

```text
Title
Paragraph
Caption
Footnote
```

允许在所在 Column 内重新 Flow。

---

# 九、这样“排版一致”的定义也需要调整

不是：

> 每一个中文字都必须落在原英文字符的位置。

而应该是：

> **保持论文视觉拓扑一致。**

例如原来：

```text
Paragraph A
    ↓
Figure 3
    ↓
Caption
    ↓
Paragraph B
    ↓
Equation 6
    ↓
Paragraph C
```

翻译后仍然：

```text
中文 A
   ↓
Figure 3
   ↓
中文图注
   ↓
中文 B
   ↓
Equation 6
   ↓
中文 C
```

这个比 bbox 像素一致重要得多。

---

# 十、甚至可以增加一个“局部微重排”算法

比如一个中文段落多了 3 行。

不要立刻失败。

按照：

```text
Level 0
原 bbox 放置
        ↓ 放不下

Level 1
调整字间距/行距
        ↓ 还放不下

Level 2
当前 Column 向下扩展
        ↓

Level 3
推动后续 FLOW 元素
        ↓

Level 4
跨栏 / 下一页继续
        ↓

Level 5
局部重新分页
```

但是：

```text
公式
图片
表格
```

作为 Anchor。

也就是：

> **Anchor + Flow Layout**

我认为这是你这个项目非常关键的技术路线。

---

# 十一、再进一步：翻译 Agent 和排版 Agent 完全解耦

不要：

```text
TranslationAgent
   ↓
直接生成 PDF
```

改成：

```text
             PDF
              ↓
        Document Parser
              ↓
          Paper AST
              ↓
    ┌─────────┴──────────┐
    ↓                    ↓
Semantic Pipeline    Layout Pipeline
    ↓                    ↓
Translation          Visual Tree
Terminology              ↓
Review               Anchor Detection
    ↓                    ↓
Translated AST       Layout Constraints
    └─────────┬──────────┘
              ↓
        Composition Engine
              ↓
          Render PDF
              ↓
          Visual QA
```

这时候系统里的 Agent 负责：

```text
理解
翻译
术语
上下文
审校
```

而**代码算法**负责：

```text
bbox
字体
换行
坐标
碰撞
分页
图像
公式
```

不要让 AI 去解决坐标，也不要让 bbox 算法决定语义。

---

# 十二、最后再加一个非常重要的 Visual QA

PDF 生成以后，不要认为任务完成。

把：

```text
原始 Page 3
翻译 Page 3
```

分别渲染成图片。

然后检查：

```text
是否文字压图？
是否文字压公式？
是否出现大片空白？
是否超出页面？
Figure 是否丢失？
Equation 是否丢失？
Table 是否变形？
Column 是否串栏？
是否有文本截断？
```

可以：

**程序检测 + Vision Model 二次检测。**

形成：

```text
翻译
 ↓
排版
 ↓
Render
 ↓
Visual QA
 ↓
发现 Page 5 Paragraph 13
与 Equation 6 overlap
 ↓
只重排 Paragraph 13
 ↓
Render Page 5
 ↓
重新 QA
```

而不是：

```text
Page 5 有问题
→ Page 5 保留英文
```

## 最终我建议你把现在的异常处理彻底换掉

现在：

```text
碰撞
→ 保留原文

保护内容丢失
→ 保留整个 Block

页面失败
→ 保留整个 Page
```

改成：

```text
                    异常
                     │
       ┌─────────────┼──────────────┐
       ↓             ↓              ↓
    语义异常       结构异常         排版异常
       │             │              │
   重新翻译       AST修复        Local Reflow
       │             │              │
       └─────────────┼──────────────┘
                     ↓
                  局部重试
                     ↓
                    QA
                     ↓
              仍无法自动解决
                     ↓
                标记人工审校
```

**“保留原文”应该从正常 fallback 机制降级为最后一道兜底。**

你现在看到：

> **有 5 处保留原文**

未来更合理的提示应该变成：

> **全文自动翻译完成。检测到 5 个复杂区域，其中 4 个已通过语义重建/局部重排自动修复，1 个需要人工确认。**

这才更像真正可以落地的专业论文翻译 Agent。

而且我认为这里最值得你现在优先重构的并不是换一个更强的大模型，而是把数据中间层统一成：

**`Paper AST + Visual Layout Tree + Element Mapping + Anchor/Flow Layout`**。

这四个东西一旦建立起来，你现在列出的 5 类问题基本就从“不断打补丁”变成了几个边界清晰、可以分别解决的工程问题。
